# Сценарий демонстрации

Пошаговый сценарий, демонстрирующий полный жизненный цикл проекта — от
публикации до завершения и отзыва — а также работу администратора.

## Подготовка

1. Поднять базу и применить миграции, засеять демо-данные:
   ```bash
   npm run db:up
   cd apps/api && npx prisma migrate deploy && npx prisma generate && cd ..
   npm run seed:demo
   ```
2. Запустить API и веб:
   ```bash
   npm run dev:api
   npm --prefix apps/web run dev
   ```
3. Открыть веб-приложение в браузере.

## Сценарий 1. Основной цикл проекта

1. **Вход заказчика** — войти как `customer@example.com`.
   Показать дашборд: приветствие, личные метрики по статусам проектов,
   быстрые действия.
2. **Создание проекта** — «Создать проект»: указать название, описание,
   категорию, диапазон бюджета. После сохранения проект открывается со
   статусом `OPEN`.
3. **Каталог проектов** — открыть «Проекты»: показать фильтры по статусу,
   категории, поиск, сортировку, переключатель «Мои проекты».
4. **Выход и вход исполнителя** — войти как `contractor1@example.com`.
5. **Отклик на проект** — открыть проект заказчика, отправить отклик:
   цена, срок, сопроводительное сообщение.
6. **Уведомление заказчику** — вернуться в аккаунт заказчика: в шапке —
   значок с непрочитанным уведомлением «Новый отклик».
7. **Принятие отклика** — заказчик открывает проект, в блоке «Отклики»
   нажимает «Принять». Проект переходит в `IN_WORK`, исполнитель
   фиксируется. Исполнитель получает уведомление «Ваш отклик принят».
8. **Завершение проекта** — заказчик переводит проект в `DONE`.
   Исполнитель получает уведомление «Проект завершён».
9. **Отзывы** — на завершённом проекте заказчик и исполнитель оставляют
   друг другу отзыв с оценкой. Рейтинг отображается в профиле.

## Сценарий 2. Профиль и навыки

1. Открыть «Профиль»: показать заполненность профиля, статистику,
   рейтинг и отзывы.
2. Редактирование профиля: имя, «о себе», навыки с автоподсказками.
3. Раздел «Безопасность»: смена email и смена пароля (с индикатором
   надёжности).

## Сценарий 3. Администрирование

1. Войти как `admin@example.com` — открывается админ-панель.
2. **Статистика** — сводные метрики по пользователям, проектам, откликам.
3. **Пользователи** — список с поиском и фильтрами; открыть карточку
   пользователя.
4. **Блокировка** — заблокировать пользователя с указанием причины и срока.
   Показать, что заблокированный не может войти (видит причину и дату).
5. **Модерация** — на странице проектов админ может принудительно отменить
   или удалить проект; на странице откликов — удалить отклик.
6. **Быстрый переход** — со страницы проекта администратор кликает по
   имени пользователя и попадает сразу в его карточку для модерации.

## Сценарий 4. API и документация

1. Открыть Swagger UI — `http://localhost:3000/api/docs`.
2. Показать сгруппированные по тегам эндпоинты, схемы запросов и ответов.
3. Выполнить `POST /auth/login`, скопировать токен, нажать **Authorize**.
4. Выполнить защищённый запрос (например, `GET /projects`).
